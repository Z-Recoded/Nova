Nova Controller

One feed: escalations, tier proposals, dispatch outcomes, and labeling — swipe or tap.

What am I looking at?

Switches panel — Nova's important flags, grouped by category. Bright green = on, dim = off. Tap to toggle. Auto-Dispatch Loop (the old "Board Watch") is whether the headless dispatch loop is allowed to run unattended right now.

Stories rail — real counts from the last 24 hours. Dispatches = how many times the loop attempted to run something (successful or not, not "tasks completed"). Merged/discarded = how many of those you've since reviewed and decided on.

Feed filters — the chips/search/date row above the Feed. Chips toggle which card types show (tap "All" to reset to everything); the search box matches against a card's task name/ID; the date dropdown hides anything older than the chosen window. Purely a local display filter — it never changes what data gets fetched or re-ranks anything, and resets if you reload the page.

Escalation cards — a headless run paused mid-task to ask you a real question. Tap an option, or type a free-text answer, to resume that exact session.

Tier cards — Nova proposes how safe a task is to hand to an unattended run: autonomous, needs review, or manual only, plus a confidence level and its reasoning. The Accept button's label always names Nova's proposed tier for that specific card (e.g. "Accept: needs review" means accepting sets this task to needs review) — it changes per card, it's not a fixed action. Override requires you to write why — that reasoning is the whole point, not a formality. Both buttons are optimistic, same as label cards below — the card collapses immediately with a few seconds to undo before the decision actually saves.

Dispatch outcome cards — a record of a past run or review decision. Read-only, tap "show summary" to expand.

Tool approval cards — the coding agent (Aero interactive lane only, not headless dispatch) paused before running a command matching a risky pattern (e.g. pip install, git rebase) and is waiting on you. Approve lets it run for real; Deny sends it back as a refusal the model reacts to. Left untouched long enough, it times out and is treated the same as a denial. Submits immediately on tap — unlike label cards below, a real process is genuinely blocked mid-turn waiting on this decision, so there's no swipe-and-undo delay here.

Label queue cards — real training-data judgments waiting on you.

Tool call — was calling this tool a good call (right tool, reasonable), or is it something Nova shouldn't have called at all? Note: this is a simplified single judgment — the underlying data actually distinguishes "was the right tool" from "was the result actually used," but today's swipe combines both into one, so a case like "reasonable call, result ended up unused" can't be captured separately yet.

Blend flag — did a fiction answer mix details from two different characters? Swipe right if it's fine as-is; swipe left (or tap red) if it genuinely needs a written correction, which opens a text box instead of committing immediately.

Verify DPO pair — is an already-written correction (from Claude via nova_corrector.py, or written by hand here) actually good? Swipe right to confirm it, swipe left to flag it as needing rework. This is separate from Blend flag above — that's "does this need a correction written," this is "is the correction that got written actually good."

DPO pairs toward fine-tune — live count of corrected pairs in logs/training_flags.jsonl against the 100-pair floor nova_finetune_phi4.py requires before a real training run. Refreshes every 15 seconds.

Headless dispatch spend — real is actual metered dollars charged (only dispatches that ran on the funded API key). notional includes every dispatch, including ones that ran on your own Claude Code subscription — those cost no extra money, so notional will usually read higher than real. There's no live per-second cost during an active run — claude -p only reports its final cost once a dispatch finishes, so this widget shows historical totals (today, last 7 days), not the in-flight run's running cost. The in-flight widget above shows a "· subscription" or "· metered" tag instead, so you can tell at a glance whether the run happening right now is free or billed.

Qwen3 8B swap-trigger progress — how close the accumulated coding-agent transcripts are to the ~30-50 diverse real tasks Phase 3.5 wants before evaluating a local-model swap (20% of that count held out, never trained on). Normally a real combined count across both machines, over a command-restricted SSH connection either direction. If the other machine can't be reached right now (most commonly: the Aero is asleep), it says so directly in the sub-line rather than showing a number that looks complete but isn't.

Swipe right or tap the green button for the positive judgment, swipe left or tap the red button otherwise.

Worktrees — every open, disposable git worktree on both machines (not the main checkout), oldest first. merged (green) means that branch's work is already in master — likely safe to clean up. prunable (red) means git itself thinks the worktree's directory is gone or broken. locked (gray) means git won't let it be removed without unlocking first. Read-only — this page doesn't delete anything for you. Refreshes every 60 seconds (slower than other widgets since checking the other machine's worktrees costs a real SSH round-trip). Same as the Qwen widget above: if a machine can't be reached right now (most commonly: the Aero is asleep), that machine's section says so directly instead of just showing nothing.

Discover — empty for now. Depends on Nova Tutor, which hasn't been built yet.

This panel lives in the same file as the UI it explains, so it can't silently go stale as the Feed changes.
